# tech-radio

技術記事を毎日自動収集し、Claudeが本質的な記事だけを選別してラジオ台本を作るシステム。
単なる機能アップデートや製品リリースの告知は選別から外し、設計判断・失敗談・実践知など中身のある記事だけを台本に採用する。ただし話題性のある新規リリースなどの注目すべき記事は例外的に採用する。

## 仕組み

実行基盤はClaude Routines(スケジュール実行のクラウドエージェント)。
1つのRoutineが、収集から台本の保存までを次の流れで担う想定。

1. `go run .` が RSS フィードを収集し、`candidates.json` に書き出す
2. Claudeが `candidates.json` を読み、採用/不採用を選別して台本を作る
3. 台本を `archive/YYYY-MM-DD.md` としてコミットする

このうち実装済みなのは1のみで、2以降は未着手。
`candidates.json` は収集結果を選別に渡すための中間ファイルであり、コミット対象には含めない。

## 記事の収集

`go run .` を実行すると `main.go` が各RSSソースから記事を集め、`candidates.json` に書き出す。

収集元は取得先ごとに独立したパッケージとして `rss/` 配下に置く。

```
rss/feed.go        収集した記事1件を表す共通モデル Feed
rss/zenn/          Zennのトピック別フィードを収集する
rss/aws/           AWS News Blogのフィードを収集する
```

フィードの形式はソースによって異なる(タイムゾーン表記がGMT表記だったり数値オフセットだったりする、など)。
そのため各パッケージは取得とXML解析を自分だけで完結させ、他のソースと共有しない。
新しい取得先を増やしたいときは、既存のパッケージに手を入れず `rss/<ソース名>/` を追加するだけでよい。

現在の収集対象は以下のとおり。

- Zenn: aws, mysql, ai, go の各トピック
- AWS News Blog

## ローカルでの実行

Go 1.21以降が必要(`log/slog`、`slices` パッケージを使用しているため)。

```sh
go run .
```

実行すると、リポジトリ直下に `candidates.json` が生成される。
